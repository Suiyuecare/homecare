# 人工帳單與收款：本機功能切片

本切片提供管理者與財務可操作的人工公司帳單與已收款保存流程，不宣稱複製原平台的官方計價、帳務、申報或正式憑證功能。使用合成測試資料；未讀取私人資料庫、Portal binding、環境秘密或原平台帳密。

## 可操作範圍

- `/billing-documents` 列出本機構帳單，25筆分頁，可依編號、人工計價依據、備註搜尋，以及月份、狀態篩選。
- 新增草稿先選1至100筆明細，再以一般名稱、數量、單價（元）欄填寫；不要求使用者輸入JSON。草稿可調整明細筆數，減少明細須明確確認；實際減少在儲存草稿後生效。
- 草稿詳情顯示個案姓名與案號快照、月份、編號、人工明細與總額，可填寫人工計價依據後確認開立。
- 已開立詳情顯示有效已收總額及未收餘額，可登錄人工已收款，查看每筆詳情與版本歷程，取消已收款紀錄，以及在沒有有效收款時作廢帳單。
- 開立、作廢、已收款登錄與取消均有共用確認介面。取消原因在本次提交必填，不能把舊備註當作本次原因。
- 表單沿用共用編輯、失敗輸入保留、dirty discard、焦點與context失效處理。元輸入透過BigInt轉整數分，拒絕負數、科學記號與第三位小數。

## 保存與授權

`billing-documents` 七個可提交欄位：`caseId`、`month`、`number`、`lineItems`、`sourceReference`、`status`、`note`。`lineItems` 每筆僅接受 `label`、`quantity`、`unitPriceCents`，1至100筆；數量1至10000，單價0至1000000000整數分。伺服器用BigInt相乘與累計，再檢查可精確保存範圍，衍生 `summary: { amountCents }`。伺服器在每次草稿保存及開立時，依目前同機構個案資料保存 `caseSnapshot: { id, name, caseNo }`；開立後快照與計價內容鎖定，作廢保留當時快照。客戶端不得提交這兩個衍生欄位。

`payment-receipts` 七個可提交欄位：`billingDocumentId`、`date`、`amountCents`、`method`、`reference`、`status`、`note`。金額僅接受1至1000000000整數分；方式為現金、轉帳、其他。這是人工作業後的已收款紀錄，API不執行付款、轉帳、扣款、退款或對外訊息，也不自動改寫父帳單版次。

管理者與財務可讀寫兩類資料，督導與居服員一律403；伺服器在解析查詢、body之前檢查角色。新增資料及操作均限定同機構，目前帳單父個案不存在、跨機構或快照識別錯置時，帳單與其收款不可讀寫；每份歷程也核對自己的父項識別與SQL版次。資料在generic records、不可改寫record_versions及audit內保存。POST沿用idempotency；PATCH必須提交目前version並以CAS拒絕過期覆寫；不提供DELETE。

## 狀態與限制

| 類別／原狀態 | 允許操作 | 必要條件 |
| --- | --- | --- |
| 新帳單 | 建立draft | 同機構個案、有效月份、唯一編號、完整明細 |
| draft | 編輯draft、改issued | 個案／月份／編號不可換；開立須人工計價依據 |
| issued | 改voided | 只接受status及本次note；全部有效收款須先取消 |
| voided | 唯讀 | 不可恢復、改寫或重用編號 |
| 新收款 | 建立active | 同機構可見issued父帳單；本次＋有效已收總額不可超收 |
| active收款 | 改cancelled | 只接受status及本次note；原日期／金額／方式／依據／父項鎖定 |
| cancelled收款 | 唯讀 | 不可恢復、改寫或刪除 |

收款上限的父帳單與既有有效收款會在同一generic idempotency SQLite交易內重新讀取、驗證及保存。兩筆並行收款超過剩餘額度時，只接受可容納的一筆，拒絕另一筆，不產生失敗操作的record、version或audit。

## 查詢與介面驗證

清單查詢閉合接受 `page`、`pageSize`、`q`、`status`、`month`、`caseId`；收款另接受 `billingDocumentId`。未知、重複、空狀態／月份／關聯、非正整數分頁與過長搜尋拒絕422。帳單只搜尋編號、人工計價依據、備註；收款只搜尋方式代碼、核對依據、備註，不搜尋JSON、UUID、個案快照或未核定明細欄。單筆不接受query；歷程只接受 `page`、`pageSize`、`compare=previous`。

帳單詳情為了完整核對未收餘額會讀取目前所有收款，至多100頁、每頁100筆；發現不完整、重複、筆數改變或超出一萬筆時拒絕顯示確定餘額，提供重新讀取。收款頁面每次列25筆，搜尋與狀態篩選保留在目前對話內。新增收款保存前仍由伺服器重讀目前總額；畫面餘額不是放寬伺服器限制的依據。

可直接執行：`node --test tests/billing-documents.test.mjs tests/billing-document-editor.test.mjs`。2026-10-10本批實跑29項通過（15項隨機埠真HTTP、14項純編輯與金額測試），涵蓋角色、機構、跨機構父項current/history隱藏、SQL歷程版次、所有狀態限制、整數分、並行超收拒絕、失敗零寫、冪等、CSRF、CAS、CRLF與未改欄保留，以及完整保存ack。父任務另外負責入口整合、共用財務歷程顯示、完整回歸與瀏覽器證據。

## 尚未宣稱的規則

尚無官方費率、自付額／補助、月額度、正式核銷、帳單自動由服務紀錄產生、信用折讓、稅額、付款、銀行對帳或正式發票／收據效力。本切片不回算或修改既有服務計價快照。正式主機、HTTPS、Portal發布與真實機構上線不屬於這次本機驗證成果。

# 核閱服務轉人工帳單草稿

本批是本機可操作的人工核對工作流；不宣稱已實作正式自付、補助、捨入、申報或付款演算法。

管理者或財務明確指定同機構個案與月份，選取 1 至 100 筆已核閱服務，逐筆輸入整筆人工總額與依據，先零寫入預覽，再確認原子生成現有帳單草稿。金額使用精確整數分，原核閱試算只供核對，不能預填或當正式價格。每筆原紀錄可以保存多個服務項目及數量，完整映射到一筆人工帳單明細，數量固定 1。

來源保留原核閱版次、完整試算、人員姓名／員編與服務項目原價格／數量。現在時薪或項目價變更不回算。保存時重新驗證目前成員授權、同機構父案／員工／完成班次、來源 CAS、SQL 安全版次及不可改寫版本。預覽不是授權，重送快取同樣重新驗證來源及授權。

`billing-service-origins` 是現有 records 內部實體，沒有公開 CRUD、額外表或遷移。一次保存帳單、固定來源、兩筆版次及稽核；任一失敗整筆回滾。來源從草稿起占用，作廢也不自動釋放。一般帳單頁繼續使用既有編輯、開立、收款、收款取消與作廢流程，原生成來源不被改寫。

「已產生帳單及來源」可搜尋、分頁及重讀保存來源，明確區分生成時人工金額、原核閱試算與目前帳單金額／狀態。一般帳單 DTO 不新增旗標或來源欄位。共同依據、每行依據與備註保留人工輸入的 CRLF 及前後空白，單行編號和明細名稱仍各自守門。

兩個 POST 專屬最多 1 MiB 輸入；全部完整回應（來源清單、預覽、生成／快取 ACK、來源清單與單筆）最多 2 MiB，超過即 413，不截斷、省略或保存部分結果。可明確縮小來源選取、搜尋範圍或 pageSize。壞 JSON、缺不可改寫版本、危險 SQL 版次、重複來源或無法確認的內部追溯一律阻擋，不自行修補。

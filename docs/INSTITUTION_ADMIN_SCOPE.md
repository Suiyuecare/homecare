# 機構行事曆與申訴管理

本次為 RM07 的本機作業切片，不宣稱原平台等價、正式營運驗收或上線。機構行事曆是共同人工行事紀錄，不改排班、請假、假額、工時、積分、薪資，不送外部訊息。

## 權限與保存

- `institution-events`：同機構四個既有角色可讀取全部機構行事與其保存歷程；只有管理者、督導可新增、修改或取消。
- `complaints`：只有同機構管理者、督導可讀取及維護；財務、居服員在解析內容或查詢前一律拒絕。不新增個案或員工授權。
- 每次修改帶目前 `version`，衝突拒絕覆寫；新增沿冪等鍵，保存與 immutable version/audit 同一交易。不提供硬刪除。
- 申訴受理人、負責人、相關員工及個案必須在同機構，歷史員工停用不使原紀錄失效。受理／負責人為人工指定員工，實際保存操作者由 audit 記錄，不互相猜測。

## 機構行事曆

八欄：標題、日期、開始時間、結束時間、分類（會議／訓練／行政／其他）、地點、備註、狀態（啟用／取消）。使用同日 HH:mm，結束晚於開始；單行標題最多200字、地點300字、備註10000字。取消或恢復保留歷程。不可記錄個案敏感內容，四角色共讀的說明必須可見。

## 申訴案件

十二欄：標題、受理日、分類（服務品質／人員／安全／費用／其他）、內容、受理員工、負責員工、相關個案、相關員工、處理紀錄、處理結果／取消原因、結案日、狀態。內容、處理紀錄及結果最多10000字。此為人工案件紀錄，不宣稱法定時限、自動調查、責任判定或外部通報。

狀態規則：新增只有「已受理」；已受理可轉處理中或取消；處理中可轉結案或取消；已結案與已取消只能更正同狀態內容。結案與取消必須記錄結果／原因；結案必須填有效結案日且不早於受理日，其他狀態不得填結案日。更改狀態由 app-owned 確認視窗明示後果，不提供自動重開。

## API

共用 `GET/POST /api/{entity}`、`GET/PATCH /api/{entity}/{id}`、`GET /api/{entity}/{id}/history`，history 支援精確 `compare=previous`。缺版不跳版、實際 audit 操作者保留。

清單封閉查詢：`page`、`pageSize`（預設25、最大100）、`q`（最多200字）、`status`、`category`，行事曆 `date` 或申訴 `receivedDate`。未知、重複、空日期／分類／狀態與非法日期拒絕；query 搜尋只查公開業務文字，不查關聯ID。history 只接受 `page/pageSize/compare`。

## 介面

沿 APM token、ui.js 的 table/search/pagination/form/dialog/toast，native select/date/time 及手機單欄。新建／編輯／完整查看／精確版本歷程共用同一狀態語彙；列表每次讀取伺服器分頁，搜尋草稿與條件留記憶體。表單失敗保留輸入，CAS 衝突要求重新讀取；保存成功須確認 id/org/version/送出欄位。機構切換、角色切換、路徑或父畫面失效中止並忽略晚回應，不輸出到 client storage。

編輯先與控制項的初始顯示值比對：textarea 將 CRLF／CR 顯示為 LF，單行欄保留前後空白；未修改的欄位完全省略，不因原生控制項換行處理或 trim 改寫原值。只對明確修改的文字沿伺服器既有 trim 契約，並確認未送出的十二／八個業務欄仍精確保持。此 payload adapter 沿共用 openForm，不新增對話框或更動後端規則。

## 驗收邊界

合成 HTTP tests 驗證角色、跨機構、同機構參照、CSRF、CAS、冪等、狀態轉移、日期、strict query、歷程與失敗零寫。必須另完成桌機與390px瀏覽器操作、長文、焦點、失敗重試及狀態確認後才標示本機整合完成。正式規則、正式資料移轉、主機、Portal 與人工作業 UAT 另驗。

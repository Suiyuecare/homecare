# 0.78.1 全系統回歸與修正

本輪以工廠合成資料、記憶體／暫存資料庫與隨機本機連接埠，執行全部 90 個已配置命令。範圍包含個案、員工、計畫、排班、服務核閱、人工費薪、表單、附件、歷程、報表、內部提示、問卷、Portal／APM 與合成還原。正式帳號、私人資料庫及正式公司登入不屬於合成測試。

修正五類程式問題：

- 請求讀取資料期間若角色、機構權限或本人綁定已失效，寫入仍可能沿用先前授權。現在於資料讀取完成後重新確認身份、權限、CSRF 與請求來源；真 HTTP 測試驗證拒絕與零後續寫入。
- 忙碌按鈕的文字轉場造成舊標籤與「處理中」重疊。保留焦點、尺寸與一般／減少動態，三種按鈕於前五個畫面更新均只顯示忙碌標籤。
- 無互動的狀態通知攔截下方滑鼠與觸控。通知持續使用 aria-live，點擊可穿透至原操作。
- 列印報表最後一頁露出螢幕底色。紙本根畫布改為白色，螢幕 APM 配色保持；七種實際 PDF 仍驗完整文字、重複表頭與安全邊界。
- 同機構其他舊個案的非文字姓名／空編號，使人工接觸足跡無法開啟。只使用個案共用的安全文字投影作為選項；識別碼、機構、重複及完整分頁檢查保持，原資料和歷程不變。

測試修正包含財務 CSV 與慢回應攔截的查詢模式同步、PDF 外部工具的可配置路徑，以及合成來源副本納入必要的忽略規則／範例設定。保留原失敗與真實退出碼，未放寬業務斷言或個別測試時間限制。

完整程式測試 2,060 項通過。全部90個已配置命令均取得原生退出碼0的完整覆蓋；修正後重測取代對應失敗，原始失敗仍保留。CI 以 Node 22.16／24 各驗完整程式測試，六組恰好一次涵蓋剩餘全部配置；合成加密演練的臨時口令只經 stdin，不存放或發布秘密。GitHub 結果以相同提交的 Actions 紀錄確認。

像素檢視由各檢查者另列實際觀看的畫面；生成 PNG 不視為已觀看。服務報表 14 欄的部分日期會折成兩行，但完整值仍在安全邊界內。外部官方設計稽核工具存在詞法解析逾時，保留逾時紀錄；經既有私人修正解析器的檢查不冒充官方工具通過。正式計價、薪資、資格、定位、申報與介接仍需核定。

公開倉庫只含可公開程式、合成測試與文件。GitHub 上傳及 CI 不代表持久主機、HTTPS、正式 Portal 發布或真實營運 UAT 已完成。

## CI 曝露的執行環境需求錯誤

原22.13宣告缺少目前原子交易守門所需的SQLite isTransaction，第一次GitHub全量驗證實際2060項中116項失敗，Node24的2060項通過；原失敗保留。支援環境現在明確為Node22.16+（22.x）與24.x，最低版也跑完整測試。啟動先以短暫記憶體資料庫確認能力，不支援即於建立資料目錄或開啟持久資料庫前拒絕；原子性守門全部保留。[Node SQLite官方文件](https://nodejs.org/download/release/v22.16.0/docs/api/sqlite.html#databaseistransaction)。

## Linux 報表文字驗收的字碼等價

四套員工／訓練／請假／證照報表的 Linux 原始失敗 PDF 已逐份核對：完整長欄位可見、順序與全部邊界正確，但 Noto CJK 字型的 PDF ToUnicode 將「長」映為 U+2ED1「⻑」。既有 NFKC 不會將此補充部首轉回 U+9577。只在 PDF 驗收的文字比較加入這一個已證明的等價映射；依據 [Unicode 17 Equivalent Unified Ideograph](https://www.unicode.org/Public/17.0.0/ucd/EquivalentUnifiedIdeograph.txt)。原始 PDF、擷取文字、資料、CSV 與畫面皆不改動。

四份同一位元組原 PDF 在原驗收下均退出 1，加入該映射後全部完整驗收退出 0；仍要求全部40列各一次、每個保存欄位的完整連續文字、每頁重複表頭、A4邊界和無背景／隱藏資料。原失敗與字碼／像素證據另存，不以縮短字串、刪除斷言或放寬時間限制換取通過。個別 Linux 流程與最終全量 CI 以對應提交的 Actions 結果為準。

## Portal 還原與 CI 診斷的非同步邊界

一次公開完整 CI 的 Portal 合成還原於 G8 失敗，原非零退出碼保留；相同流程獨立 Linux 診斷的 G1–G8 完整通過，原始失敗的精確位置因當次只存私人錯誤雜湊而無法確認，不宣稱已證明其原因。程式檢視找到具體的驗收缺口：工作台標題會先於資料及個案／員工參照讀取出現。測試現在另要求這些讀取完成後才顯示的「工作摘要」，再進行快照、撤權、重載或換庫，並在未來失敗時只輸出測試程式碼位置。十三表唯讀、原cookie／期限、nonce與binding、BLOB和回復／提升的原斷言及逾時均保持；沒有自動重試。最終接受仍以相同提交完整 CI 的結果為準。

CI 的截尾診斷及停用／恢復 workflow commands 標記改由同一 stdout 串流順序輸出，避免 stdout／stderr 合併時的重新排序；原生退出碼、12000字元上限、加密演練診斷抑制與stdin臨時口令清零保持。

## 補齊獨立驗證命令

原90命令的本機基線及其逐次來源／失敗保持。另盤點兩套獨立的舊報表月份安全與十一表合成還原瀏覽器流程，以及兩套合成備份／Portal備份CLI演練，納入常態清單；現在為94個配置命令（93個必要命令，另含已配置請假歷程），六組互斥執行92個runtime命令，程式測試和来源檢查由兩個Node作業執行。

兩個獨立瀏覽器的原非零紀錄保留。舊oracle依無跨日模式取得資料，與目前畫面明確使用calendar-two-day-v1的完整日期DTO／CSV不同；只同步預期查詢模式，不改保存資料、恢復程式、原快照價格／原文或完整DTO／CSV／十一表六trigger及附件BLOB斷言。擴充後的完整驗收仍以相同提交的原生結果為準。

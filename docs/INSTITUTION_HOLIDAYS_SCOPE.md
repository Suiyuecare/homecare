# 機構人工假日設定範圍

本功能保存每個機構自行指定的假日、工作日、停止服務日及其他日期。這是人工管理紀錄，尚無官方假日、例休、排班、加給、假額、申報或發票計算效力。不會因保存或查詢而拒絕排班、更動服務快照、計算薪資或發送外部訊息。

## 欄位及狀態

Entity：`institution-holidays`；頁面：`/#/institution-holidays`，標題「機構人工假日」。

| 欄位 | 必填 | 保存規則 |
| --- | --- | --- |
| `date` 指定日期 | 是 | 完整 `YYYY-MM-DD`，0001–9999年，拒絕不存在日期；可更正，舊日期留在歷程 |
| `title` 名稱 | 是 | 非空白單行文字，最多200字；保存原前後空白 |
| `kind` 人工指定類型 | 是 | `holiday` 機構指定假日、`working-day` 機構指定工作日、`closure` 機構停止服務日、`other` 其他人工指定；新增需明確選擇 |
| `sourceReference` 人工設定依據 | 否 | 最多2000字，保存人工文件識別或來源；不推定法定核准 |
| `note` 備註 | 否 | 最多10000字，保存完整原文 |
| `status` 紀錄狀態 | 系統預設 | 新增為 `active` 使用中；`inactive` 已停用由明確操作保存；可恢復使用 |

伺服器產生 `id`、`orgId`、`version`、`createdAt`、`updatedAt`。資料及 ACK 限定六個業務欄位與這五個 metadata 欄位；未知鍵、非字串內容、getter、symbol 或不合法 metadata 不展開。前端 textarea 初始顯示會把 CRLF／CR轉成 LF；未改動欄位不提交，因此其他欄位更正不改寫原長文、換行與前後空白。明確改動的文字照輸入保存。

同機構同一天最多一筆使用中的紀錄，與類型或名稱無關。停用紀錄不占用日期，可另新增有效設定；若該日已有其他有效設定，原紀錄恢復使用或有效紀錄移到該日會回應409。停用與恢復均明確確認、保留歷程，不硬刪除。停用中仍可更正人工欄位。其他機構同日設定互不影響。

## 權限及保存

只有已登入的 `admin`、`supervisor` 可讀取及維護目前機構設定。`finance`、`caregiver` 在 query／body解析之前回應403；其他機構 ID 的 current／history／PATCH回應404。清單與詳情均使用相同閉合 DTO 守門；JSON無法解析、null、array、未知巢狀鍵、SQL與資料ID／機構／安全整數版次不符的匯入紀錄不顯示。查詢及歷程不寫入。

新增 POST 使用冪等鍵；相同鍵、相同內容重試回傳原完整保存結果，變更內容重用鍵回應409。PATCH必須提交目前安全整數 `version`，使用共用 CAS 與交易；所有編輯及狀態確認在同一表單生命週期使用穩定冪等鍵。重複日期檢查在共用保存交易內重新讀取。若既有資料無法完整核對或可讀筆數與機構資料實際筆數不符，保存回應409，避免忽略壞資料後建立重複設定。版次已達安全上限時拒絕再保存。拒絕的操作不新增紀錄、歷程、audit或冪等結果。

前端只有在完整已保存六欄、識別碼、機構、下一版次及固定建立時間均符合送出內容時才完成保存並提示成功。保存回應不符時保留輸入及冪等鍵。元件、路由、機構、使用者或角色情境改變後，晚到回應不重開視窗、不更新舊頁、不提示成功；已經由伺服器提交的資料由重新讀取確認。

## Query 與歷程

- 清單 `GET /api/institution-holidays`：僅 `page`、`pageSize`、`q`、`status`、`year`，各最多一次。預設第1頁、每頁25筆，最多100筆；年度必須四位0001–9999，拒絕尾端換行或空白。省略年度查詢全部年度。
- 搜尋最多200字，僅搜尋日期、名稱、人工類型中文、人工依據及備註，不搜尋 metadata 識別碼。結果依日期、名稱、識別碼排序；前端每頁25筆。
- Current `GET /api/institution-holidays/:id`：不接受 query。
- 歷程 `GET /api/institution-holidays/:id/history`：僅 `page`、`pageSize`、`compare=previous`。逐版核對閉合 DTO、同機構 ID、固定建立時間及安全 SQL 版次；日期可更正，因此不固定舊版日期。
- `POST`、`PATCH` 使用共用 CSRF、Origin、角色與機構守門。未提供 DELETE；保留停用紀錄供追溯。

## 共用介面及驗收

使用既有 APM 公司視覺、ordinary form、確認、詳情、搜尋、25筆分頁、版本歷程與錯誤回復管線，不新增 CSS、依賴或第二套 dialog owner。

新增與編輯為日期、名稱、類型、人工依據、備註五個正常控制項。狀態另外透過「停用／恢復使用」確認；詳情與型別化歷程顯示所有六欄及保存版次。預設當年查詢並顯示查詢年度，使用者可明確查其他年度或全部年度。頁面可見人工參考範圍，不把紀錄標成法定核准。

必要驗收包括：合成 memory SQLite／隨機 loopback HTTP；雙角色 CRUD；同日並行建立僅一筆成功；停用釋放日期及恢復衝突；跨機構404與禁用角色403；CSRF／Origin／CAS／冪等；未知 query／欄位及不合法日期；原 CRLF／空白保存；不良 ACK輸入保留及同鍵重試；current／history壞 JSON與安全版次隱藏；查詢及失敗零寫；真瀏覽器 ordinary form、明確確認、完整型別化歷程、375px／390px及情境變動。

本批17項 pure／validator及8項真HTTP測試共25項已通過。專屬真瀏覽器9組工作流通過，沒有 pageerror；最新 desktop／375px／390px共19張截圖均實際以原始解析度檢視，包含手機橫向捲動到操作欄與向下捲動到完整歷程長文。手機寬表使用既有可左右捲動的表格，長歷程使用既有可上下捲動的 modal及固定底部關閉鈕；不宣稱所有欄位在同一張手機畫面同時可見。首輪瀏覽器最後一步自寫測試等候錯誤的既有頁面標題失敗，失敗證據保留；修正 selector後重跑通過，產品守門未放寬。這些驗收是本機合成資料證據，不代表正式網址、HTTPS或 Portal 已發布；未檢視原平台未知格式，不宣稱原平台等價或官方規則完成。

# 服務轉人工薪資草稿介面

v0.72已完成本機正式程式接線後的HTTP、瀏覽器及像素驗收（accepted_local）；正式主機與Portal發布另驗。只處理同機構管理者與財務的本機人工紀錄，不宣稱法定工資、資格、保險、稅費、加班演算法或付款效力。

## 完整操作

入口 `/service-payroll` 的頁名為「服務轉薪資」，由 `mountServicePayroll(container, {isCurrent})` 載入。先人工選擇員工與月份，再搜尋已核閱服務、跨個案加入待核對來源，最多100筆。未加入服務時顯示簡潔說明；選取、移除、搜尋、分頁、來源詳情與預覽皆不寫入。

每個服務紀錄生成一筆人工加項。金額欄一開始空白，使用既有精確元／分解析器，必須人工明確填寫；可以明確輸入0，不由原時薪、服務分鐘、數量或試算單價計算。逐筆填明細名稱、金額及核對依據，再填結算編號、共同人工核定依據與備註。共同依據最多500字元、逐筆依據2000、備註10000；文字原文保留前後空白與換行，不截斷長文。

先預覽完整原服務快照、每筆人工金額與依據、建立時目前員工姓名／員編及加減淨額，再以共用確認對話框明確生成。後端原子保存原有 `payroll-statements` 草稿與封閉的 `payroll-service-origins` 來源。已生成服務永久標示薪資已導入，取消草稿也不釋放；帳單占用與薪資占用分開，同一服務可以各自生成一次。

「已產生薪資及來源」模式會重新 GET 保存來源與目前結算。完整呈現生成當時人工加項／淨額、目前加項／減項／淨額、目前狀態／版次，以及原核閱當時的員工姓名、員編、試算時薪、時間、服務項目、數量與價格。原 Source12 沒有保存個案姓名；清單的「個案（讀取範圍時參考名稱）」來自本次同機構個案名單，明示非核閱當時姓名，原個案識別碼可展開查閱。

「前往人工薪資結算」連結使用既有草稿編輯、人工加減項、覆核、關帳、取消及型別化版本歷程 owner；不另造薪資狀態表單，不改初版來源，不把關帳描述成付款。

## 保存與失效

共用 `ui.js` 的表單、預覽、確認、詳情、搜尋、表格、分頁及錯誤 owner 沿 APM CIS；沒有新 CSS、視覺 token、原生 alert／confirm／prompt 或新依賴。列表固定每頁25筆，來源詳情按原查詢及版次重新讀取。欄位及 DTO 的巢狀物件／陣列封閉驗證，包括 own accessor、未知鍵、稀疏陣列、非整數分、錯誤來源時間或不一致淨額；不展開未知 JSON，不呼叫不安全 getter。

preview 只接受與本次輸入／完整來源一致的封閉回應。create 必須帶已核對 previewHash 與冪等 key，保存 ACK 必須包含完整初版與來源，並與預覽相符才顯示成功。真保存但 ACK 不完整時，表單及原文保留，再以相同完整 payload、hash 及 key 重試，避免第二份草稿。409 使舊預覽失效且保留輸入。其他失敗保留所有欄位。

同機構角色權限由伺服器先檢查，再解析 body／query；瀏覽器持續核對原 context、登入者、機構、角色與路由。會員撤回、切換路由、重新渲染或父 `isCurrent()` 失效後的晚回應不顯示成功、不更新新頁面。源與草稿版次由 API 重新核對；後續原結算 PATCH 沿既有 CAS，不以 email 推定角色。

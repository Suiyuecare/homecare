# 服務來源轉人工帳單與永久週期班整組移日

版本0.71，已完成本機程式整合及合成驗收（accepted_local）。本文件不宣稱正式規則、部署或原平台對等完成。

## 核閱服務轉帳單

管理者及財務從同機構、同個案、同月份的已核閱服務選取1至100筆。每筆完整服務對應一筆人工帳單總額，輸入明細名稱、明確整數分及人工依據；原核閱時薪、服務數量及價格快照另完整保存，不自動套用試算或捨入。

來源清單、人工輸入、零寫入預覽及確認後原子建立帳單草稿是一個完整流程。帳單、不可變生成來源、版本、稽核及重送鍵在原交易內保存。來源含草稿即占用；後續開立、修改草稿、收款、取消收款及作廢沿既有人工帳單流程，作廢不釋放來源。來源追溯同時分列生成當時金額及目前帳單金額／狀態。

專用路由為`GET /api/service-billing/sources`、`POST /preview`、`POST /create`、`GET /origins`及`GET /origins/:billId`。保存需要`Idempotency-Key`及本次`previewHash`。來源和追溯列表必填`caseId`及`month`，其他只接受單一`page/pageSize/q`；單筆及寫入不接受query。preview/create專屬1MiB請求，其他API上限不變；完整來源回應超限全拒，不省略內容。

伺服器在查詢及讀取body之前核對目前角色／機構會員，交易內在重送快取查找之前重驗身份、原服務版次及預覽內容；新結果及重送回應均核對不可變來源與初版帳單。內部`billing-service-origins`存於既有records／record_versions，不開泛用CRUD，不新增schema。SQL安全版次、完整JSON與不可變head不一致即拒絕，不修補或略過。

## 永久週期班整組移日

管理者及督導在既有永久週期班設定中，按原產班日期範圍載入完整可編輯班次，人工指定非零整數移動日數、原因、每筆保存版次，先預覽每筆原產班日期／目前日期／目標日期，再確認整組保存。沿既有`adjustments/preview`及`adjustments/commit`路由，保存須重送鍵。

原產班識別、不可變原日期、原設定版次及快照保留；只改目前班次日期及班次版次。驗證原不可變第一版與現在不可變head。僅經伺服器私有操作範圍確認的班次可整組移日，泛用PATCH仍禁止修改已連結班次日期，不接受client bypass旗標。

先組成全部最終目標，再核對彼此及外部班次、請假、照顧計畫效期、人員／服務項目、所有服務紀錄鎖定及CAS。任何一筆失敗，整組班次／版本／稽核／重送紀錄全部回滾。重新產班按原slot識別既有班次，移日後不重複產生替代班次。

原occurrence八欄保持；只有經證明目前日期與原link.date不同時附加`movedDate`，UI必須驗證欄位存在條件及與目前日期完全一致。舊ISO時間原文不改寫；需使用既有明確改時段流程另填HH:mm後才能移日。跨夜支援仍另需跨排班、請假、服務核閱、歷程及報表相容驗收。
